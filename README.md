# 🚚 Выявление рисков задержки доставки — CargaPronto

Проект предсказания задержек доставки на этапе оформления заказа с использованием профилирования клиентов (сегментации) как инструмента предиктивной аналитики.

---

## 📋 О проекте

**Заказчик:** логистическая компания **CargaPronto**.

**Проблема:** задержки доставки — ключевой фактор оттока клиентов и финансовых потерь. На момент старта проекта риск задержки оценивается постфактум, когда повлиять на исход уже нельзя.

**Идея:** использовать профилирование клиентов (сегментацию по географии и поведению) как предиктивный признак. Если модель «знает», к какому сегменту относится клиент, она точнее прогнозирует риск задержки ещё на этапе оформления заказа — и логистика успевает принять меры: скорректировать сроки, сменить маршрут или тип перевозки.

**Подход:** комбинация классического ML (логистическая регрессия, CatBoost) и кластерной сегментации (KMeans по геокоординатам и поведенческим признакам RFM+). Кластерные метки становятся дополнительными признаками для прогнозной модели.

---

## 🎯 Цель и критерий успеха

> Доказать бизнесу, что профилирование клиентов (выделение сегментов по географии и поведению) повышает качество прогноза риска задержки доставки по сравнению с моделью, использующей только признаки самого заказа.

**Формальный критерий успеха:** ROC-AUC > 0.75 на тестовой выборке.

## 📊 Данные

### `ds_s18_customers.csv` — профили клиентов (20 652 записи)

| Столбец | Тип | Описание |
|---------|-----|----------|
| `customer_id` | int64 | Уникальный идентификатор клиента |
| `customer_lat` | float64 | Широта |

| Столбец | Тип | Описание |
|---------|-----|----------|
| `order_id` | int64 | Уникальный идентификатор заказа |
| `customer_id` | int64 | Связь с таблицей клиентов |

## 📈 Ключевые этапы пайплайна

### 1. Предобработка и EDA
- Преобразование `order_date` → datetime, создание признаков `order_month`, `order_weekday`, `order_hour`.
- Удаление географических аномалий (долгота вне диапазона `[-125, -20]`) с каскадным удалением связанных заказов.
- Корреляционный анализ признаков с целевой переменной через коэффициент phik.

### 2. Разделение данных
- `GroupShuffleSplit` гарантирует, что все заказы одного клиента попадают в одну выборку — утечки данных по клиентам нет.
- Пропорции: train 60% / valid 20% / test 20%.

### 3. Базовые модели
- LogisticRegression и CatBoostClassifier обучаются на признаках заказа (без кластерных).
- Результаты на валидации фиксируются как baseline для сравнения.

### 4. Геокластеризация
- KMeans на масштабированных координатах (`customer_lat`, `customer_lon`).
- Число кластеров — методом локтя.
- Визуализация кластеров и центроидов на карте.
- **Важно:** KMeans и Scaler обучаются только на train-выборке, затем применяются к valid и test.

### 5. Поведенческая кластеризация
- Признаки: `recency`, `total_orders`, `total_sales`, `avg_discount`, `return_rate`.
- Масштабирование → KMeans → t-SNE для визуализации.
- Характеристика сегментов («активные лояльные», «спящие», «возвратчики» и т. д.).

### 6. Финальные модели
- Кластерные метки (гео + поведенческие) добавляются к признакам заказа.
- Эксперимент: кластеры как категориальные (OneHot) vs числовые.
- Перебор K для обоих типов кластеров как гиперпараметра → оптимизация ROC-AUC на валидации.

### 7. Тестирование
- Лучшая модель оценивается на тестовой выборке.
- Метрики: ROC-AUC, матрица ошибок, важность признаков.

## 🔐 Защита от утечки данных

Особое внимание уделено корректности ML-пайплайна:

- **GroupShuffleSplit** — клиенты не пересекаются между выборками.
- **KMeans и Scaler** обучаются только на train; к valid/test применяется `transform` / `predict`.
- Удаление географических аномалий в профиле клиента → каскадное удаление связанных заказов (целостность данных).

## 🚀 Практическое применение

При успешном подтверждении гипотезы модель может быть интегрирована в систему оформления заказов CargaPronto:

- **Скоринг в реальном времени:** при оформлении заказа модель оценивает вероятность задержки.
- **Автоматические рекомендации:** для заказов с высоким риском — корректировка сроков, смена маршрута или типа перевозки.
- **Сегментные политики:** различные SLA и логистические сценарии для разных клиентских сегментов.
